1
Executive Summary
SmartEvent AI is a full-stack web application designed to modernise event management within colleges
and universities. The platform targets three distinct user roles—students, organizers, and
administrators—and provides each with purpose-built workflows backed by Firebase's serverless
infrastructure.
The product is intentionally scoped to pure web technologies (HTML, CSS, Vanilla JavaScript) without any
frontend framework dependencies, keeping the barrier to entry low for academic environments while still
delivering a premium, startup-quality user experience. The monochrome design language draws
inspiration from Apple, Linear, Vercel, and Notion—emphasizing clarity, whitespace, and cinematic
typography over decorative excess.
Key differentiators include a simulated AI recommendation engine, live seat availability counters,
QR-based attendance verification, and a real-time analytics dashboard that rivals commercial event
platforms.

7
Feature Specifications
7.1 Authentication System
Firebase Authentication handles all identity management. No passwords are stored by the
application—Firebase manages credential hashing and token lifecycle.
Sign-Up Flow
   Form fields: Full Name, Institutional Email, Password, Confirm Password, Role selection (student /
organizer).
   Client-side validation: name (≥ 2 chars), email regex, password strength (≥ 8 chars, 1 uppercase, 1
number, 1 symbol).
   Password strength meter: 4-segment bar, color transitions white→silver→gray→black.
   On submit: createUserWithEmailAndPassword → write user doc to Firestore users collection →
redirect.
   Error states: email-already-in-use, weak-password, network-request-failed—each displays specific
toast.
Sign-In Flow
   Email/password: signInWithEmailAndPassword.
   Google OAuth: signInWithPopup(GoogleAuthProvider) → upsert user doc in Firestore.
   Role detection: read users/{uid}.role → route to /dashboard.html or /admin.html.
   Remember me: Firebase persistence set to LOCAL by default (IndexedDB).
   Forgot password: sendPasswordResetEmail with branded redirect URL.
Session & Security
   onAuthStateChanged listener initialises role-based UI on every page load.
   Unauthenticated users attempting protected routes are redirected to /login.html with returnUrl query
param.
   JWT ID tokens are managed by Firebase SDK; no manual token storage.
   Logout: signOut() → clear local state → redirect to /index.html.
7.2 Event Discovery & Search
   Full-text client-side search over event title, description, tags, and venue fields (in-memory after
Firestore fetch).
   Filter panel: Category (multi-select checkboxes), Date range (start / end pickers), Status (Upcoming /
Live / Past), Seat availability toggle.
   Sort options: Date Ascending, Date Descending, Popularity (registrationCount), Newest First.
   Live search: debounced 300 ms after keystroke; results update without page reload.
   URL-encoded filter state: sharing the URL reproduces the same filter view.

7.3 Event Registration & Ticketing
   Check: user must be authenticated; seats > 0; registration deadline not passed; user not already
registered.
   Atomic Firestore transaction: decrement events/{id}.seatsAvailable, create registrations document,
add to user's registeredEvents array.
   Post-registration: animated success modal with confetti (monochrome particle burst), ticket preview,
and download CTA.
   Ticket data structure: {ticketId, userId, eventId, userName, eventTitle, date, venue, qrPayload,
generatedAt, status}.
   QR payload: JSON string of {ticketId, userId, eventId} encoded via qrcode.js library, rendered as
300×300 px canvas.
   Download: ticket rendered to HTML canvas with event branding → exported as PNG via
canvas.toDataURL().
   Cancellation: allowed up to 24 hours before event; reverses Firestore transaction; ticket status set to
'cancelled'.
7.4 QR Code Attendance System
   Organizer/Admin opens /admin.html#scanner → prompted for camera permission.
   jsQR library decodes frames from getUserMedia video stream at 15 fps.
   On decode: look up ticketId in Firestore registrations collection.
   Ticket states: valid (not yet used) → mark attendance, show green SUCCESS overlay;
already-scanned → show amber WARNING; invalid/not-found → show red ERROR.
   Attendance write: create attendance/{ticketId} doc with {ticketId, userId, eventId, scannedAt,
scannedBy}.
   Offline fallback: manual ticketId text entry with Firestore lookup.
   Audio cue: Web Audio API beep on successful scan (300 Hz, 150 ms).
   Scan log: running list in sidebar showing last 20 scans with status badges.
7.5 AI-Inspired Features (Client-Side Simulation)
No external AI API is used. Intelligence is simulated via deterministic JavaScript scoring algorithms applied
to local Firestore data.
Smart Recommendation Engine
   Score each event against user's interest tags (exact match = 10 pts, parent category = 5 pts).
   Boost events with registrationCount > 50 by +3 pts (popularity signal).
   Penalise events the user has already registered for (excluded).
   Sort by descending score; surface top 6 as 'For You' card carousel.

9.2 Firestore Security Rules (Outline)
   users: read → owner or admin; write → owner (limited fields) or admin.
   events: read → all authenticated; create → organizer or admin; update/delete → owner organizer or
admin.
   registrations: read → owner student or admin; create → authenticated student; update/delete →
owner or admin.
   attendance: read → organizer of event or admin; create → organizer or admin; no delete.
   notifications: read/update → owner; create → admin (server-triggered only); no delete.
   All rules require request.auth != null (no anonymous access).
   Disabled users: all write rules include !resource.data.disabled check on users/{uid}.

12.1 Performance
   Lighthouse Performance Score ≥ 85 on desktop, ≥ 75 on mobile (3G throttle).
   First Contentful Paint < 1.5 s on broadband.
   Time to Interactive < 3.5 s on broadband.

   Firestore reads: use composite indexes; limit queries to minimum required documents.
   No synchronous localStorage reads on critical render path.
   Chart.js canvases rendered only when the analytics tab is active.
12.2 Accessibility
   WCAG 2.1 Level AA as target.
   All interactive elements reachable via keyboard; focus rings visible (2px white/black offset).
   ARIA labels on icon-only buttons and form inputs.
   Color contrast ratio ≥ 4.5:1 for body text; ≥ 3:1 for large text.
   Modal focus trap while open; focus returns to trigger on close.
   AOS animations: respects prefers-reduced-motion media query (animations disabled).
   Alt text on all meaningful images; decorative images aria-hidden='true'.
12.3 Security
   All Firestore operations protected by Security Rules (see Section 9.2).
   Client-side role checks are UX convenience only; server Rules are the authoritative gate.
   Input sanitisation: all user-generated content passed through DOMPurify before innerHTML insertion.
   Firebase App Check (optional v2 hardening): prevents API abuse from non-app clients.
   CSP header (via firebase.json): restricts script sources to self + trusted CDN domains.
   HTTPS enforced; no HTTP fallback.
   No API keys stored in JavaScript beyond Firebase config (which is safe to expose client-side by
design).
12.4 Responsiveness
   Mobile first CSS: base styles target 320 px; larger breakpoints layered with min-width media queries.
